# Live for Gear - ALS City Performance Shaders

Modified FlightGear ALS (Atmospheric Light Scattering) shaders and effects
for OSM-generated **roads** and **buildings**, aimed at two problems on the
stock shaders:

1. **Night and Day visibility** — roads and buildings went near-black at night, with
   flat, over-saturated streetlight color and no head/tail light contrast.
2. **GPU cost** — several stock code paths ran unconditionally every pixel
   even when the feature they belonged to was disabled (normal mapping,
   reflections, snow, cars on roads without traffic, etc.).


## Benchmark & Test Environment Settings

Tuned and tested on a GTX 1060 at 1080p, FlightGear 2024.1.x, with
building/cloud shadows disabled and default OSM scenery. Aimed for 60 FPS in high-building-density on viewport at the lowest GPU utilization achievable (~50% in rural areas, ~70% in medium size towns/cities, ~80-100% in overcrowded areas), by reducing shader work that's imperceptible while flying (such as window reflections, normal maps, etc.), while keeping essential features like lightmaps intact.

Baseline sweeps were done with the free-camera UFO, which has no cockpit
render cost of its own. To check how the changes hold up with a real,
systems-heavy aircraft under load, the same Osaka position was also flown
with the [A320 Family](https://github.com/legoboyvdlp/A320-family) addon,
since its detailed cockpit (multiple live MFDs, high-poly model) is one of
the more GPU-demanding options for this kind of low-altitude city test —
closer to a worst-case than a light GA aircraft would be.

## What's in this repo

| File | Purpose |
|---|---|
| `road-ALS-ultra.frag` | Road fragment shader (main variant) |
| `road.eff` | Road effect; wires `rain-enabled` back on |
| `building-ALS.vert` | Building vertex shader; computes haze color per vertex |
| `building-ALS-fast.frag` | Building fragment shader (fast/lightweight ALS variant) |
| `building.eff` | Building effect; wires new snow uniforms through |


## Installing

Replace the matching files under your FlightGear install's
`Shaders/` and `Effects/`, keeping the original file names. Back up the originals first —
there is no in-sim toggle to switch back to stock behavior.

`road.eff` calls out `Shaders/model-ALS-ultra.vert`,
`Shaders/road-ALS-ultra.frag`, and several shared includes
(`hazes.frag`, `cloud-shadowfunc.frag`, `shadows-include.*`,
`clustered-include.frag`); those shared includes are stock and are not
part of this repo.

## Changes

### Roads

**Night visuals**
- Fixed lamp light being multiplied by the near-black asphalt texture,
  which made streetlights read far dimmer than intended.
- Fixed `mixedcolor` never being assigned in the WS3.0 variant (read as
  garbage in the reflection-disabled path).
- Added a night-only asphalt floor color so roads stay visible instead of
  going pure black.
- Replaced the flat "glowing line" lit-road look with a lamp-pool pattern
  (bright at lamp positions, dimmer between), tuned for a more realistic
  night appearance.
- Added **per-district lamp color variation**: streetlights blend between
  amber (sodium), warm white, and cool white (LED) across ~500 m cells,
  with major roads (by traffic density) pulled whiter than side streets —
  instead of one uniform color for the whole map.
- Separated head/tail lights from the streetlight accumulator so they are
  no longer dimmed by dark asphalt; they now ramp brighter at night while
  keeping the stock daytime look.

**Performance**
- `NormalTex`, `ReflMapTex`, the `Environment` cubemap, and
  `ReflGradientsTex` are now fetched only when the feature that reads
  them is actually enabled (was 5 unconditional texture fetches/pixel).
- Snow computation (incl. 2× `Noise2D`) is skipped entirely below
  `snowlevel + 220 m`, where its result was always zero anyway.
- The car-sprite block is skipped on road types that never spawn cars
  (rail, grass, tram), not just when traffic is globally disabled.
- Rain/wetness work only runs while `wetness > 0.01`; raindrop ripple
  noise is capped to a 250 m radius instead of being computed at any
  distance.
- `rain-enabled` re-enabled in `road.eff` now that its cost is gated.

### Buildings

- ALS haze base color moved from **per-pixel** (fragment shader) to
  **per-vertex** (vertex shader), removing ~9 `exp`/`pow` calls per hazed
  pixel. Toggle via `BLD_HAZE_IN_VERTEX` in the fragment shader for an
  A/B comparison against the original per-pixel path.
- Lightmap texture is no longer fetched while its factor is 0 (daytime).
- Re-added wet-wall darkening, roof snow (same altitude rule as roads),
  and a moonlight-scaled night ambient floor — features roads already
  had but buildings didn't. Requires the two new uniforms
  (`bld_snow_level`, `bld_snow_thickness`) wired through `building.eff`.

All additions are gated behind night/rain/snow uniforms and feature
flags; **daytime, clear-weather output is intended to be visually
unchanged** from the original shaders.

## Tuning constants

Defined near the top of each fragment shader:

```glsl
// roads
const float ROAD_NIGHT_FLOOR   = vec3(0.10, 0.10, 0.13); // min. night asphalt color
const float ROAD_LAMP_GAIN     = 1.7;                     // streetlight brightness
const float ROAD_MIN_ILLUM     = 0.50;                    // unlit-road-type floor (highways)
const float ROAD_LM_BASE       = 0.20;                    // lamp light vs. asphalt albedo
const float CAR_LIGHT_GAIN     = 1.3;                      // head/tail light night boost
const float RAIN_RIPPLE_DIST   = 250.0;                    // rain ripple cutoff (m)
const float DISTRICT_SIZE      = 500.0;                    // lamp-color cell size (m)
const float DISTRICT_COLOR_AMOUNT = 1.0;                   // 0 = old uniform color

// buildings
#define BLD_HAZE_IN_VERTEX 1   // 0 = revert to per-pixel haze (slower, for A/B testing)
#define BLD_WET_SNOW       1   // 0 = disable wet/snow/moonlight additions
```

A `DISTRICT_DEBUG` switch in the road shader renders a red/green/blue
palette instead of the real lamp colors, useful for checking the district
cell size visually before tuning `DISTRICT_SIZE`.

## Known limitations / not verified

- **Not compiled or profiled in-sim.** Shaders were checked with
  `glslangValidator` (GLSL 1.20, fragment+vertex link-tested) but not run
  inside FlightGear. Uniform names assumed to be bound by `building.eff`
  / `road.eff` (e.g. `moonlight`, `wetness`, `bld_snow_level`) were not
  confirmed against the actual property tree.
- **No controlled before/after GPU benchmark.** GPU%/frame-time numbers
  gathered during tuning used varying camera distance and weather
  presets, so they reflect scene load more than shader cost. Run an A/B
  comparison (same position, time, and weather, old vs. new shaders back
  to back) before relying on this for GPU-constrained setups. The A320
  Family sweep described above is a single realistic-load data point,
  not a substitute for that A/B pass.
- **District colors may repeat across scenery tiles.** The district grid
  is keyed off model-local vertex position, which can repeat per tile;
  a world-space offset uniform would remove this if it becomes visible.
- **Possible haze banding on large building faces in heavy weather.**
  Moving haze color to the vertex shader relies on interpolation across
  the face; not checked on large, sparsely-tessellated walls under fast
  fog changes (e.g. thunderstorms).
- Snow and reflection/normal-map paths were not exercised with real
  scenery during this work.
